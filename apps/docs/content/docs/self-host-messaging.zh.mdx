---
title: 自托管消息
description: 在自己的 Orvilo 服务器配置飞书、Slack、钉钉、企业微信、Telegram 和微信。
---

自托管消息由服务器运维人员配置。在 `server_configured` 模式下，Orvilo App
展示连接状态、当前用户有权使用的路由控制和身份绑定流程。凭据、平台授权和断开连接
均由服务器端管理。

本指南覆盖飞书、Slack、钉钉、企业微信、Telegram 和个人微信。
**微信目前仅支持文字私聊**，不支持群消息和媒体。

## 1. 准备部署

先完成[自托管快速上手](/self-host-quickstart)，登录并创建工作区。以下命令在服务器的
仓库根目录执行。仓库与 backend 镜像应来自同一版本。微信命令要求镜像包含
`/app/orvilo-messaging`；验证当前源码时使用 `make selfhost-build`。

在部署原有的 `.env` 中配置公网 HTTPS 地址：

```dotenv
FRONTEND_ORIGIN=https://app.example.com
ORVILO_APP_URL=https://app.example.com
ORVILO_PUBLIC_URL=https://api.example.com
```

把示例域名换成自己的域名。手机和 IM 用户必须能访问 App 地址。保留快速上手中的
HTTPS 反向代理和 WebSocket 转发；跨设备身份绑定不能使用 localhost 或私网地址。
服务器还需要能主动连接所启用的平台。

生成独立的消息配置模板：

```bash
scripts/messaging-self-host-setup.sh init \
  --app-url https://app.example.com \
  --api-url https://api.example.com \
  --env-file .env.messaging
```

脚本创建权限为 `0600` 的文件。通过部署的秘密存储或服务器编辑器填写，保留权限，
不要提交到仓库。保留原有 `.env`，Compose 仍需要其中的数据库和登录配置。

## 2. 选择工作区和密钥

使用登录到此部署的 [Orvilo CLI](/cli) 查询完整 UUID：

```bash
orvilo --profile selfhost --server-url https://api.example.com login
orvilo --profile selfhost workspace list --output json
orvilo --profile selfhost workspace member list WORKSPACE_UUID --output json
```

将 `WORKSPACE_UUID` 替换为所选工作区的 `id`。在 `.env.messaging` 中，将
`ORVILO_MESSAGING_WORKSPACE_ID` 设为该 ID，将
`ORVILO_MESSAGING_INSTALLER_USER_ID` 设为 owner/admin 成员的 `user_id`，
不是成员记录本身的 `id`。

工作区连接的 `ORVILO_MESSAGING_AGENT_ID` 留空。若只连接一个 Agent，使用
`orvilo --profile selfhost --workspace-id WORKSPACE_UUID agent list --output json`
查询后填写该 Agent 的完整 UUID。此启动导入模板会为选定范围内的每个平台配置一个连接。

为每个启用的平台分别生成加密密钥：

```bash
openssl rand -base64 32
```

写入下文对应的 `ORVILO_*_SECRET_KEY`。更新既有连接时沿用原密钥；替换密钥会导致
数据库中的已有凭据无法解密。未启用平台的密钥和凭据留空。

修改 `.env.messaging` 后，在执行下文终端检查前导出变量。单独 `source` 不会导出
新定义的变量：

```bash
set -a
. ./.env.messaging
set +a
```

下文的平台查询命令需要 `curl` 和 `jq`，只展示平台标识，不输出 token 值。

## 3. 配置平台

### Slack

1. 运行 `scripts/messaging-self-host-setup.sh slack-manifest`。在
   [Slack API Apps](https://api.slack.com/apps) 中选择 **Create New App → From a
   manifest**，粘贴输出的 YAML。
2. 将 app 安装到 Slack workspace，把 `xoxb-` Bot User OAuth Token 写入
   `SLACK_BOT_TOKEN`。
3. 在 **Basic Information → App-Level Tokens** 生成带 `connections:write`
   权限的 `xapp-` token，写入 `SLACK_APP_TOKEN`，保持 Socket Mode 开启。
   两个 token 必须属于同一个 app。
4. 设置 `ORVILO_SLACK_SECRET_KEY`，按上文重新载入 `.env.messaging`，查询 Bot 身份：

```bash
curl -fsS https://slack.com/api/auth.test \
  -H "Authorization: Bearer ${SLACK_BOT_TOKEN}" \
  | jq -e 'select(.ok == true) | {team_id, user_id}'
```

把返回的 `team_id` 写入 `SLACK_TEAM_ID`，`user_id` 写入 `SLACK_BOT_USER_ID`。
`SLACK_APP_ID` 可从 app 的 Basic Information 页面复制；启动导入也能从 app-level
token 解析该值。仓库中的 manifest 包含 Orvilo 使用的消息事件和权限。
自托管 Slack 使用服务器主动发起的 Socket Mode，不需要托管 OAuth 客户端凭据或回调地址。

### 飞书

1. 在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用并启用**机器人**能力。
   把 App ID、App Secret 写入 `LARK_APP_ID`、`LARK_APP_SECRET`，设置
   `LARK_REGION=feishu` 和 `ORVILO_LARK_SECRET_KEY`。
2. 为文字私聊和群内 @ 消息开启应用身份权限 `im:message.p2p_msg:readonly`、
   `im:message.group_at_msg:readonly`、`im:message:send_as_bot`。参见飞书官方
   [机器人配置步骤](https://open.feishu.cn/document/develop-an-echo-bot/faq?lang=zh-CN)。
3. 重新载入 `.env.messaging`，用此应用自己的凭据查询机器人身份：

```bash
LARK_TENANT_ACCESS_TOKEN="$(
  jq -n '{app_id: env.LARK_APP_ID, app_secret: env.LARK_APP_SECRET}' \
    | curl -fsS https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal \
        -H 'Content-Type: application/json' --data-binary @- \
    | jq -er 'select(.code == 0) | .tenant_access_token'
)"
curl -fsS https://open.feishu.cn/open-apis/bot/v3/info \
  -H "Authorization: Bearer ${LARK_TENANT_ACCESS_TOKEN}" \
  | jq -e 'select(.code == 0) | {bot_open_id: .bot.open_id}'
unset LARK_TENANT_ACCESS_TOKEN
```

把返回的 `bot_open_id` 写入 `LARK_BOT_OPEN_ID`。`LARK_TENANT_KEY` 和
`LARK_BOT_UNION_ID` 是可选身份信息，已知时可填写。完成第 4 节的 backend 启动后，
回到**事件与回调**，选择**使用长连接接收事件**并订阅 `im.message.receive_v1`。
飞书保存此选项时要求已有运行中的长连接。发布应用，使目标成员可用，再发送一条私聊验证。
这些步骤针对中国版飞书；托管 App 的国际版 Lark 新建入口仍未开放。

### 钉钉

1. 在[钉钉开发者后台](https://open-dev.dingtalk.com)创建企业内部应用，启用机器人，
   将消息接收方式设为 **Stream 模式**。
2. 开启机器人消息发送权限 `qyapi_robot_sendmsg`；添加 `qyapi_chat_manage` 以获取
   Bot/群信息，并发布给需要使用的组织成员。
3. 将 **Client ID / AppKey** 写入 `DINGTALK_CLIENT_ID`，**Client Secret /
   AppSecret** 写入 `DINGTALK_CLIENT_SECRET`，设置 `ORVILO_DINGTALK_SECRET_KEY`。
   如果控制台提供独立的 robot code，填写 `DINGTALK_ROBOT_CODE`；否则默认使用 client ID。

### 企业微信

1. 在[企业微信管理后台](https://work.weixin.qq.com/wework_admin/frame#apps)创建或编辑
   智能机器人，开启 **API 模式 → 长连接**。
2. 将 **BotID** 写入 `WECOM_BOT_ID`，长连接专用 **Secret** 写入 `WECOM_SECRET`。
   这里使用智能机器人 Secret，不是 webhook 的 Token/EncodingAESKey 或应用 CorpSecret。
3. 设置 `ORVILO_WECOM_SECRET_KEY`；`WECOM_BOT_NAME` 是可选显示名称。服务器连接
   `wss://openws.work.weixin.qq.com`，详细配置见
   [官方长连接指南](https://developer.work.weixin.qq.com/document/path/101463)。

### Telegram

1. 打开官方 [@BotFather](https://t.me/BotFather)，发送 `/newbot`，设置名称和用户名。
   把返回的 HTTP API token 写入 `TELEGRAM_BOT_TOKEN`，设置
   `ORVILO_TELEGRAM_SECRET_KEY`。
2. 重新载入 `.env.messaging`，确认 Bot 身份并移除已有 webhook，使 Orvilo 可以轮询：

```bash
curl -fsS "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/getMe" \
  | jq -e 'select(.ok == true) | .result | {id, username}'
curl -fsS -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/deleteWebhook" \
  --data 'drop_pending_updates=false' \
  | jq -e 'select(.ok == true) | {ok, description}'
```

将返回的 username 写入 `TELEGRAM_BOT_USERNAME`。启动 Orvilo 前停止其他轮询此 Bot
的程序；Telegram 不允许 webhook 与轮询同时运行，也不允许多个程序争用同一个轮询流。

### 微信

设置 `ORVILO_WEIXIN_SECRET_KEY` 以及第 2 节的工作区/安装者范围，并按下文启动
backend。手机需要登录个人微信；不需要企业微信组织或开发者 AppID。

在自己的服务器运行运维命令：

```bash
docker compose --env-file .env --env-file .env.messaging \
  -f docker-compose.selfhost.yml exec backend \
  /app/orvilo-messaging weixin-auth
```

用微信扫描终端中的二维码并确认授权。微信要求验证码时，在终端提示处输入。
保持命令运行，直到它报告安装 ID。命令使用 backend 当前配置的数据库与加密密钥，
处理支持的区域跳转，并将授权后的 iLink 凭据加密写入数据库，不输出 Bot token。

此命令仅在 `server_configured` 模式可用。可用非密钥参数 `--workspace-id`、
`--installer-user-id`、`--agent-id` 覆盖对应环境值。二维码过期后重新运行命令获取新码。
Ctrl-C 可取消本次操作；在验证码提示处关闭输入也会取消。

模板中的 `WEIXIN_BOT_ID`、`WEIXIN_ILINK_USER_ID`、`WEIXIN_BOT_TOKEN` 和可选
`WEIXIN_BASE_URL` 用于导入运维人员已通过合法 iLink 授权取得的凭据。使用
`weixin-auth` 时将这些字段留空；此命令无需导入，也不要求
`ORVILO_MESSAGING_BOOTSTRAP=true`。仅填写变量名称不会授权微信账号。

## 4. 载入配置并检查

要在启动时导入其他五个平台的 token/app 配置，在 `.env.messaging` 中设置
`ORVILO_MESSAGING_BOOTSTRAP=true`。仅使用微信运维扫码命令时保持 `false`。
重新载入文件并检查部署配置：

```bash
set -a
. ./.env.messaging
set +a
scripts/messaging-self-host-setup.sh check
docker compose --env-file .env --env-file .env.messaging \
  -f docker-compose.selfhost.yml up -d backend frontend
```

后续 Compose 命令也要传入这两个 env 文件。消息文件覆盖同名基础值；需要保留的已有
平台凭据和加密密钥也应保留在配置中。`up -d` 会重建配置发生变化的服务；`restart`
不会重新读取环境。`deploy/messaging/manifest.yaml` 说明变量名称，服务器实际读取
注入的环境变量，不直接读取这份 YAML。

`check` 检查部署参数，不验证平台授权。启动导入会加密凭据并创建或更新安装记录。
存在安装记录本身不代表平台已接受凭据，也不代表消息连接已建立。

## 5. 验证一次文字私聊

1. 在自托管 App 打开 **IM → 查看详情**，确认工作区/Agent 连接和真实运行状态。
   未连接时检查 backend 日志与平台侧应用配置。
2. 从平台向 Bot 发送简短文字。若收到身份绑定链接，打开链接，登录此工作区，再发送文字。
3. 确认文字进入 Orvilo 对话，且回复返回平台。Agent 执行还需要可用的电脑/运行时。
   微信应使用文字私聊验证。

运维人员可检查服务状态，以下命令不显示凭据：

```bash
curl -fsS https://api.example.com/readyz
curl -fsS https://app.example.com/api/config | jq '.messaging'
docker compose --env-file .env --env-file .env.messaging \
  -f docker-compose.selfhost.yml logs --tail=100 backend
```

`/api/config` 应返回 `mode: server_configured`、`setupWritable: false`。
App 的凭据生命周期接口会以 `server_managed_integration` 拒绝写入；既有身份绑定和
当前用户有权使用的路由仍可操作。若要暂停所有消息，在配置中设置
`ORVILO_MESSAGING_MODE=disabled` 并重建 backend。
`ORVILO_MESSAGING_BOOTSTRAP=false` 只停止导入，不会断开已有连接。

电脑离线时，服务器 PostgreSQL 中的安装记录、IM 会话和消息仍会保留。电脑保存自己的
Agent 会话和执行文件；换一台电脑登录不需要重新绑定 IM 身份。自托管消息不消耗
Orvilo Cloud 托管 IM 配额。
