Patchbay uses your own Slack app. Once connected, team members can DM the Bot, @-mention it in a channel, or use `/issue` to create issues.

The Slack app is installed at the Patchbay workspace level, not on a
particular computer or agent. Members can choose or switch the active agent
with `/agents`; create another Slack app only when you need a separate Bot
identity.

## Before you start

The connection must be completed by a workspace owner or admin, and ends with two credentials pasted into Patchbay:

- a Bot User OAuth Token, starting with `xoxb-`;
- an App-level Token, starting with `xapp-`.

## 1. Create the Slack app from a manifest

Open [Slack API Apps](https://api.slack.com/apps), click **Create New App → From a manifest**, pick the Slack workspace, then paste the following under **YAML**:

```yaml
display_information:
  name: Patchbay
features:
  app_home:
    home_tab_enabled: false
    messages_tab_enabled: true
    messages_tab_read_only_enabled: false
  bot_user:
    display_name: Patchbay
    always_online: true
  slash_commands:
    - command: /issue
      description: Create a Patchbay issue
      usage_hint: "[description]"
oauth_config:
  scopes:
    bot:
      - app_mentions:read
      - channels:history
      - files:read
      - groups:history
      - im:history
      - mpim:history
      - chat:write
      - reactions:write
      - users:read
      - commands
settings:
  event_subscriptions:
    bot_events:
      - app_mention
      - message.im
      - message.channels
      - message.groups
      - message.mpim
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

Before creating, you can replace both occurrences of `Patchbay` with the agent's name. Do not remove scopes or events from the manifest, or DMs, channel mentions, replies, or `/issue` may stop working.

<Callout type="warning">
If this Slack app was installed before attachment support was available, add the `files:read` Bot scope and reinstall the app to the workspace. Slack does not apply newly added scopes to the existing Bot token until the app is reinstalled.
</Callout>

The Bot connects out to Slack over Socket Mode, so no public Request URL or OAuth Redirect URL is needed.

## 2. Get the two tokens

### Bot token

1. In the Slack app, open **Install App**.
2. Click **Install to Workspace** and approve the permissions.
3. Copy the **Bot User OAuth Token** — it starts with `xoxb-`.


### App-level token

1. Open **Basic Information → App-Level Tokens**.
2. Click **Generate Token and Scopes**.
3. Add the `connections:write` scope.
4. Generate and copy the token starting with `xapp-`.


## 3. Connect it to the workspace

1. In Patchbay, open **Settings → Integrations** and click **Connect Slack**.
2. Choose the workspace-level installation (or a dedicated agent route if you
   explicitly need one).
3. Paste the Bot token and the App-level token.
4. Click **Connect**.

Patchbay verifies that the two tokens come from the same app. Once connected, the page shows **Connected to Slack**.

<Callout type="warning">
Both tokens are stored encrypted on the Patchbay server. Tokens are credentials — don't put them in issues, comments, or code repositories. An app already connected to another workspace can't be reused directly; disconnect the original connection first.
</Callout>

## First use

The first time a member DMs or @-mentions the Bot, they receive an account binding link. Sign in with the Patchbay account for that workspace, then return to Slack and send the message again.

The link is single-use and expires after 15 minutes. Once it expires, message the Bot again for a new one. Multiple Bots in the same Patchbay workspace can usually reuse an existing binding if they come from the same Slack workspace.

Only members of the current Patchbay workspace can use the Bot.

## Hand work to the agent in Slack

### Direct messages

Open the Bot from **Apps** in the Slack sidebar and message it directly — no @-mention needed.

### Channels and group chats

Run `/invite @your-bot` to add the Bot to the channel first, then send `@your-bot your request`. Each thread forms its own session; for follow-ups, keep @-mentioning the Bot in the original thread.

The Bot only responds to channel messages that explicitly @-mention it. When it runs, it reads the thread's recent context within the scopes its permissions allow.

### Send files

Attach files to a DM, or to a channel message that @-mentions the Bot. They arrive as attachments on the same piece of work, so the agent reads them together with your request.

This needs the `files:read` scope — if the app was installed before attachment support existed, see the note in step 1. Each file must be 20 MiB or smaller, and one message carries at most 10. Files that are larger, still uploading, or hosted outside Slack (a Google Drive or Dropbox link, for example) are skipped; the message text still reaches the agent.

### Create issues with `/issue`

In a channel or DM, type:

```text
/issue Safari stays on the login page after a successful sign-in
```

This command needs no @-mention. Patchbay hands the description to the agent behind the current Bot, which writes up the title and body and creates the issue. Slack first shows an acknowledgment visible only to you; when the issue is created, you get a notification in your Patchbay inbox.

## Manage connections

Open **Settings → Integrations** to view all connected Slack Bots. Workspace owners and admins can disconnect them.

After disconnecting, the Socket Mode connection stops and the Bot no longer receives new messages. Existing conversations and audit records are not deleted.

## Self-hosting setup

Patchbay Cloud needs no extra configuration. A self-hosted deployment is
server-managed: the app is read-only and does not accept Slack credentials.
Follow the [self-hosted messaging deployment contract](/self-host-messaging)
and run the setup helper on the server.

```dotenv
PATCHBAY_SLACK_SECRET_KEY=<base64-encoded 32-byte key>
```

Generate one like this:

```bash
openssl rand -base64 32
```

Set `PATCHBAY_MESSAGING_BOOTSTRAP=true` with the server-owned workspace and
installer IDs, add the `SLACK_BOT_TOKEN`, `SLACK_APP_TOKEN`, team ID, and bot
user ID to the deployment secret store, then restart the API server. Keep this
key long-term: if it is rotated or lost, existing tokens can no longer be
decrypted. Do not expect a Connect button in the self-hosted app.

Account binding links use `PATCHBAY_APP_URL`, falling back to `FRONTEND_ORIGIN` when unset; it must point to a Patchbay address members can reach.

## Troubleshooting

- **Invalid token when connecting**: check the prefixes and confirm both tokens come from the same app.
- **App can't be verified**: confirm the manifest includes `users:read`, then reinstall the app after updating permissions.
- **No DM entry point**: confirm `app_home.messages_tab_enabled` is `true`.
- **No reply in a channel**: confirm the Bot has been invited to the channel and the message @-mentions it.
- **`/issue` doesn't exist**: confirm the manifest includes the slash command and the `commands` scope, then reinstall the app.
- **Files don't reach the agent**: confirm the manifest includes `files:read` and that the app was reinstalled after the scope was added, and check the file is 20 MiB or smaller.
- **The Bot doesn't run**: check whether the agent is archived and whether the [runtime](/daemon-runtimes) it uses is online.
