Patchbay CLI 既负责连接本机运行时，也可以在终端中管理工作区、issue、智能体和自动化。这里介绍常用路径；当前版本支持的参数始终以命令自身的 `--help` 为准。

## 安装

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/patchbay-ai/patchbay/main/scripts/install.sh | bash
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/patchbay-ai/patchbay/main/scripts/install.ps1 | iex
```

确认安装成功：

```bash
patchbay version
```

## 第一次连接

连接 Patchbay Cloud：

```bash
patchbay setup
```

连接自托管实例：

```bash
patchbay setup self-host \
  --server-url https://api.example.com \
  --app-url https://app.example.com
```

`setup` 会保存服务地址、打开浏览器完成登录，并启动守护进程。完成后检查：

```bash
patchbay auth status
patchbay daemon status
```

如果只需要重新登录，不想覆盖其他配置，运行 `patchbay login`。没有浏览器的环境可以先在 Web 设置中创建个人访问令牌，再输入：

```bash
patchbay login --token
```

命令会在终端中提示粘贴令牌，避免把完整值留在 shell history 中。

## 选择工作区

列出并切换默认工作区：

```bash
patchbay workspace list
patchbay workspace switch <slug>
```

之后的命令会使用这个工作区。单次命令可以通过 `--workspace-id` 临时覆盖，也可以设置 `PATCHBAY_WORKSPACE_ID`。

邀请成员：

```bash
patchbay workspace member invite teammate@example.com
patchbay workspace member invite admin@example.com --role admin
```

## 常用 issue 操作

```bash
# 查看和搜索
patchbay issue list
patchbay issue get PB-123
patchbay issue search "登录失败"

# 创建和修改
patchbay issue create --title "修复登录失败"
patchbay issue status PB-123 in_progress
patchbay issue update PB-123 --executor "Backend Agent" --no-start

# 评论和Agent 事件
patchbay issue comment list PB-123
patchbay issue comment add PB-123 --content "请先检查回归测试"
patchbay issue runs PB-123
```

长描述或评论从 stdin 读取，避免处理换行和引号：

```bash
patchbay issue create --title "升级说明" --description-stdin < notes.md
patchbay issue comment add PB-123 --content-stdin < review.md
```

查看某次执行的消息，或停止 task：

```bash
patchbay issue run-messages <task-id> --issue PB-123
patchbay issue cancel-task <task-id> --issue PB-123
```

## 智能体和 skill

```bash
patchbay agent list
patchbay agent get <agent-id>
patchbay agent create --help
patchbay agent update <agent-id> --help

patchbay skill list
patchbay skill get <skill-id>
patchbay skill import --url <skill-url>
patchbay agent skills add <agent-id> --skill-ids <skill-id>
```

导入时遇到同名 skill，默认会停止且不修改现有内容。按意图选择：

```bash
patchbay skill import --url <skill-url> --on-conflict overwrite
patchbay skill import --url <skill-url> --on-conflict rename
patchbay skill import --url <skill-url> --on-conflict skip
```

`overwrite` 只允许 skill 的创建者使用，并保留原来的 ID 与智能体绑定关系。

## 守护进程和运行时

```bash
patchbay daemon start
patchbay daemon stop
patchbay daemon restart
patchbay daemon status --output json
patchbay daemon logs --follow

patchbay runtime list
patchbay runtime rename <runtime-id> "Office Mac"
patchbay runtime usage <runtime-id>
patchbay runtime activity <runtime-id>
```

删除仍绑定活跃智能体的运行时时，命令默认拒绝。`patchbay runtime delete <id> --cascade` 会解绑这些智能体、保留其配置与历史记录，并取消它们的活动 task。

运行机制和自定义 profile 见[守护进程与运行时](/daemon-runtimes)。

## 命令概览

| 命令 | 用途 |
| --- | --- |
| `issue` | 创建、更新、分配和搜索 issue；管理评论、订阅、标签、属性与Agent 事件 |
| `project` | 管理项目及其资源 |
| `label`、`property` | 管理工作区标签和自定义属性 |
| `agent`、`skill`、`team` | 管理智能体、skill 和团队 |
| `automation` | 管理自动化、触发器和运行历史 |
| `workspace` | 创建、查看、切换工作区和邀请成员 |
| `repo` | 管理工作区仓库，并把仓库检出到本机 |
| `daemon`、`runtime` | 启停本机守护进程，查看和管理运行时 |
| `attachment` | 上传或下载附件 |
| `user profile` | 查看或更新当前用户资料 |
| `auth`、`login`、`setup` | 登录、查看认证状态和初始化连接 |
| `config` | 查看或修改当前 CLI profile 的本地配置 |
| `update`、`version` | 更新 CLI 或查看版本 |

`patchbay chat` 读取的是**智能体当前正在处理的外部聊天会话**，主要供聊天集成中的智能体使用；它不是用于浏览任意工作区对话的通用命令。

## ID 和输出格式

Issue 使用 `PB-123` 这样的 key 或完整 UUID，不接受 UUID 短前缀。

其他资源的 `list` 命令通常显示可复制的短 ID，并支持 `--full-id` 输出完整 UUID。短 ID 不唯一时，CLI 会要求增加字符或改用完整 UUID。执行任务的短 ID 还需要通过 `--issue` 指明所属 issue。

许多命令支持结构化输出：

```bash
patchbay issue list --output json
patchbay agent list --output json
```

脚本使用 JSON 输出，不解析面向终端的表格。各命令支持的输出格式和分页参数以 `patchbay <command> --help` 为准。

## Profile 与配置

默认配置保存在 `~/.patchbay/config.json`。使用 `--profile <name>` 可以隔离另一套服务地址、令牌、默认工作区和守护进程状态：

```bash
patchbay setup self-host --profile staging \
  --server-url https://api.staging.example.com \
  --app-url https://app.staging.example.com

patchbay issue list --profile staging
```

命名 profile 保存在 `~/.patchbay/profiles/<name>/config.json`。查看当前值：

```bash
patchbay config show
patchbay config show --profile staging
```

<Callout type="warning">
CLI 配置文件包含可代表你访问 Patchbay 的令牌。不要提交到仓库、上传到日志或与他人共享。
</Callout>

## 命令参考

下表覆盖当前全部顶层命令，按 CLI 自身的分组排列。所有命令都接受全局 flag `--server-url`、`--workspace-id`、`--profile` 和 `--debug`。`--output` 是逐命令注册的 flag，默认格式因命令而异：`list` 类默认表格，`get`、`create` 类多默认 JSON。完整参数以 `patchbay <command> --help` 为准。

### Core

| 命令 | 子命令 | 用途 | 关键 flag |
| --- | --- | --- | --- |
| `issue` | `list` | 列出 issue | `--status`、`--priority`、`--executor` / `--executor-id`、`--owner` / `--owner-id`、`--project`、`--metadata`（可重复）、`--limit`、`--offset`、`--sort`、`--full-id` |
| | `get <id>` | 查看单个 issue | |
| | `create` | 创建 issue | `--title`（必填）、`--description` / `--description-stdin` / `--description-file`、`--status`、`--priority`、`--executor` / `--executor-id`、`--owner` / `--owner-id`、`--reviewer` / `--reviewer-id`、`--parent`、`--stage`、`--project`、`--start-date`、`--due-date`、`--attachment`（可重复） |
| | `update <id>` | 更新 issue 字段 | 与 `create` 同类字段，另有 `--position`、`--no-start` |
| | `assign <id>` | 兼容的组合角色设置/清除 | `--to`、`--to-id`、`--unassign`、`--no-start` |
| | `status <id> <status>` | 修改状态 | `--no-start` |
| | `reorder <id>` | 在列内移动 | |
| | `search <query>` | 搜索 issue | `--limit`、`--include-closed` |
| | `children <id>` | 按阶段分组列出子 issue | |
| | `pull-requests <id>` | 列出关联的 PR | |
| | `comment list/add/delete/resolve/unresolve` | 管理评论 | `add`：`--content` / `--content-stdin` / `--content-file`、`--parent`、`--attachment`；`list`：`--since`、`--thread`、`--tail` |
| | `subscriber list/add/remove <issue-id>` | 管理订阅者 | `--user`、`--user-id`（缺省为当前用户） |
| | `label list/add/remove <issue-id>` | 管理 issue 上的标签 | |
| | `metadata list/get/set/delete <issue-id>` | 管理 issue 级键值元数据 | |
| | `property list/set/unset <issue-id>` | 设置自定义属性值 | `set`：`--name`、`--value`（`actor` / `multi_actor` 接受成员的名称、邮箱或 id） |
| | `runs <issue-id>` | 查看执行历史 | `--full-id` |
| | `run-messages <task-id>` | 查看单次执行的消息 | `--since`、`--issue` |
| | `usage <issue-id>` | 查看聚合 token 用量 | |
| | `rerun <id>` | 按当前指派重新入队执行 | |
| | `cancel-task <task-id>` | 取消运行中或排队中的 task | `--issue` |
| `project` | `list/get/create/update/delete` | 管理项目 | |
| | `status <id> <status>` | 修改项目状态 | |
| | `resource list/add/update/remove` | 管理项目附加资源 | `--type`、`--url`、`--local-path`、`--daemon-id`、`--execution-mode`（本地目录的 `in_place` / `worktree`） |
| `label` | `list/get/create/update/delete` | 管理工作区标签 | |
| `property` | `list/get/create/update/archive/unarchive` | 管理工作区自定义属性 | `create`：`--name`、`--type`（`text`、`number`、`select`、`multi_select`、`date`、`checkbox`、`url`、`actor`、`multi_actor`）、`--option`（可重复，仅 select 类型）；`list`：`--include-archived`；类型创建后不可修改 |
| `agent` | `list/get/create/update/archive/restore` | 管理智能体 | `--name`、`--runtime-id`（`create` 必填）、`--instructions`、`--model`、`--thinking-level`、`--mcp-config`、`--permission-mode`、`--max-concurrent-tasks` |
| | `copy <agent-id>` | 复制为新智能体，原智能体不受影响 | `--name`（默认为原名加 ` (copy)`）、`--runtime-id`（复制到其他运行时时必须同时指定 `--model`）、`--no-skills`；`custom_env`、`mcp_config`、`runtime_config` 等机密配置不会复制，需用与 `create` 相同的 flag 重新提供 |

| | `trigger-add/trigger-update/trigger-delete/trigger-rotate-url` | 管理定时和 webhook 触发器 | |

| | `member list/invite <email>` | 查看成员、发出邀请 | `invite`：`--role`（member 或 admin，默认 member） |
| `repo` | `list/add/remove/checkout` | 管理工作区仓库并检出到本机 | `--url`（可重复）；`checkout`：`--ref` |
| `skill` | `list/get/create/update/delete` | 管理 skill | |

| 命令 | 子命令 | 用途 | 关键 flag |
| --- | --- | --- | --- |

| 命令 | 子命令 | 用途 | 关键 flag |
| --- | --- | --- | --- |
| `auth` | `status` / `logout` | 查看认证状态；`logout` 只删除本地保存的令牌，不吊销服务端令牌 | |
| `user` | `profile get/update` | 查看或更新当前用户资料 | |

## 在其他编码智能体里操作 Patchbay

如果你的工作大多发生在 Codex、Claude Code 或 Cursor 里，可以直接在那里操作 Patchbay，
不必切回终端。[Patchbay CLI skill](https://github.com/patchbay-ai/patchbay-cli)
会教这些智能体安全地使用本页的命令：低成本地读 issue 和评论线程、通过文件写评论，
以及正确处理 mention、状态变更和指派带来的副作用。

它完全通过你已认证的 CLI 运行，本身不授予任何权限 —— 权限仍然只来自你的登录、
所选 profile 和 workspace。要求 CLI 版本不低于 v0.4.26。该仓库的 README 说明了
Claude Code 插件市场、Codex skill 安装器、Cursor 以及其他任何加载 Markdown 指令的
工具的安装方式。
