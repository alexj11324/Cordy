description: エージェントをタスクの executor に設定し、すぐに実行を開始するかどうかを決めます。
---

import { Callout } from "fumadocs-ui/components/callout";

ある作業をエージェントに継続して実行させたいときは、そのエージェントをタスクの executor に設定します。エージェントはタスクの説明と議論を読み、自身の設定とスキルで作業を進め、進捗と結果を同じタスクに書き戻します。

executor を変えずに 1 件の具体的な依頼だけを処理してほしいときは、代わりに[コメントでの @メンション](/mentioning-agents)を使ってください。

## 割り当てと実行の開始

1. タスクを開き、**Executor** をクリックします。
2. エージェントまたはチームを選択します。
3. 確認ダイアログで、これから開始するエージェントを確認します。
4. 必要に応じて引き継ぎメモを記入し、**開始**を選択します。

![割り当ての確認ダイアログ：引き継ぎメモを記入するか、まだ開始しないことを選べます](/images/docs/assign-confirm-dialog.webp)

引き継ぎメモは今回の実行にのみ適用されます。範囲、順序、今回とくに注目してほしい点の補足に使ってください。長期的に有効な要件は、タスク本文、プロジェクトの説明、またはエージェントの指示に書きます。

team を executor に設定すると、タスクの executor はチームになり、最初に実行を開始するのはチームのリーダーです。リーダーはチームの運用方針に従って、他のメンバーに作業を渡すかどうかを判断します。owner と reviewer は独立したロールです。

## 割り当て後の実行フロー

Patchbay はエージェントのために[作業](/tasks)を作成します。オンラインのランタイムが作業を受け取ると、そのマシン上の AI コーディングツールを呼び出します。進捗、コメント、結果はその後タスクに表示されます。

ランタイムが一時的にオフラインの場合、作業はキューで待機します。作業はそのランタイムに紐づいており、別のマシンに移ることはありません。

実行中のエージェントは次のことができます。

- タスクの説明、フィールド、コメントを読み取る
- 紐づけられたスキル、MCP サーバー、プロジェクトコンテキストを使う
- ローカルの作業ディレクトリでファイルを読み、コマンドを実行し、変更を加える
- コメントを投稿し、タスクのステータスを更新する

実際にできることは、エージェントの設定、ランタイム環境、あなたの実行権限によって制限されます。

## まだ開始しない割り当て

確認ダイアログの**まだ開始しない**は、executor を保存しつつ、今回の作業は作成しません。まず実行対象を確定し、背景や依存関係が整ってから開始したいときに使います。

`backlog` のタスクも、agent/team executor の設定だけでは実行を開始しません。タスクを `backlog` から移動するか、コメントで executor に依頼を続けたときに、はじめて後続の実行が生まれます。

すでに agent/team executor がいる作業を `backlog` から移動すると、同じ確認ダイアログが開きます。実行を開始するのはこのステータス変更そのものなので、同じ引き継ぎメモを書けますし、**まだ開始しない**も同じように使えます（ステータスだけ変えて、エージェントは起こしません）。この確認ダイアログは、`backlog`・`done`・`cancelled` 以外のカテゴリへ移動するときに表示されます。

この挙動は `backlog` カテゴリだけで、そのカテゴリの[カスタムステータス](/issues#カスタムステータス)もまったく同じように振る舞います。すでに `done` や `cancelled` にあるタスクは、エージェントに割り当て・再割り当てすると、すぐに実行が開始されます。

## 割り当ての権限

エージェントを割り当てられるかどうかは、その Access で決まります。

- **自分のみ**: エージェントの owner だけが実行できます。
- **特定のメンバー**: owner とリストに載ったメンバーが実行できます。
- **ワークスペース全体**: すべてのワークスペースメンバーが実行できます。

ワークスペースの owner と admin はエージェントを管理できますが、「見える」ことは「実行できる」ことを意味しません。Executor ピッカーでは、実行権限のないエージェントは選択できません。完全なルールは[エージェント](/agents#権限と-access)を参照してください。

## executor の変更と解除

executor を別のエージェントに変更すると、新しい executor による実行が新たに開始されます。owner に member を設定しても、役割が変わるだけで AI コーディングツールは呼び出されません。executor を外しても作業は作成されません。

<Callout type="warning">
executor の変更、executor の解除、タスクのステータス変更では、すでに開始された実行は停止しません。中断するには、実行ログで該当する作業を停止してください。
</Callout>

## CLI での操作

```bash
patchbay issue assign MUL-42 --to "Agent name"
patchbay issue assign MUL-42 --to-id <agent-uuid> --no-start
patchbay issue update MUL-42 --owner-id <member-uuid> --reviewer-id <member-or-agent-or-team-uuid>
patchbay issue status MUL-42 in_progress --no-start
patchbay issue assign MUL-42 --unassign
```

スクリプトでは `--to-id <uuid>` を使うと、同名のオブジェクトへの誤マッチを避けられます。UUID は `patchbay agent list --output json` または `patchbay workspace member list --output json` で確認できます。

executor の設定だけを記録し、新しい作業を作成しない場合（たとえば同じエージェントが別の実行ですでにそのタスクを処理している場合）は、`--no-start` を使用します。`issue update` と `issue status` でも同じフラグを使用できます。ロールとステータスの両方を変更する記録専用のフローでは、両方のコマンドにこのフラグを指定してください。executor の起動を抑止しても、後続のステータス変更による実行は自動では抑止されません。
