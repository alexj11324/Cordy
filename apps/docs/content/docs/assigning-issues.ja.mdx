title: イシューのロールを管理する
description: イシューの owner、executor、reviewer を設定し、すぐに実行を開始するかを決めます。
---

import { Callout } from "fumadocs-ui/components/callout";

ある作業をエージェントまたはチームに継続して実行させたいときは、イシューの executor を設定します。executor はイシューの説明と議論を読み、自身の設定とスキルで作業を進め、進捗と結果を同じイシューに書き戻します。人間の責任者には owner、引き継ぎには reviewer を設定できます。

ロールを変えずに 1 件の具体的な依頼だけを処理してほしいときは、代わりに[コメントでの @メンション](/mentioning-agents)を使ってください。

## ロールを設定して実行を開始

1. イシューを開き、**Executor**、**Owner**、または **Reviewer** を選択します。
2. そのロールのメンバー、エージェント、またはチームを選択します。
3. 確認ダイアログで、これから開始するエージェントを確認します。
4. 必要に応じて引き継ぎメモを記入し、**開始**を選択します。

![割り当ての確認ダイアログ：引き継ぎメモを記入するか、まだ開始しないことを選べます](/images/docs/assign-confirm-dialog.webp)

引き継ぎメモは今回の実行にのみ適用されます。範囲、順序、今回とくに注目してほしい点の補足に使ってください。長期的に有効な要件は、イシュー本文、プロジェクトの説明、またはエージェントの指示に書きます。

チームを executor にすると、イシューの executor はチームになり、最初に実行を開始するのはチームのリーダーです。リーダーはチームの運用方針に従って、他のメンバーに作業を渡すかどうかを判断します。

## executor 設定後の実行フロー

Patchbay はエージェントのために[タスク](/tasks)を作成します。オンラインのランタイムがタスクを受け取ると、そのマシン上の AI コーディングツールを呼び出します。進捗、コメント、結果はその後イシューに表示されます。

ランタイムが一時的にオフラインの場合、タスクはキューで待機します。タスクはそのランタイムに紐づいており、別のマシンに移ることはありません。

実行中のエージェントは次のことができます。

- イシューの説明、フィールド、コメントを読み取る
- 紐づけられたスキル、MCP サーバー、プロジェクトコンテキストを使う
- ローカルの作業ディレクトリでファイルを読み、コマンドを実行し、変更を加える
- コメントを投稿し、イシューのステータスを更新する

実際にできることは、エージェントの設定、ランタイム環境、あなたの実行権限によって制限されます。

## ロールだけ設定してまだ開始しない

確認ダイアログの**まだ開始しない**は、ロールを保存しつつ、今回のタスクは作成しません。まず担当を確定し、背景や依存関係が整ってから開始したいときに使います。

`backlog` のイシューも、割り当てだけでは実行を開始しません。イシューを `backlog` から移動するか、コメントで担当者に依頼を続けたときに、はじめて後続の実行が生まれます。

すでにエージェントまたはチームの担当者がいるタスクを `backlog` から移動すると、同じ確認ダイアログが開きます。実行を開始するのはこのステータス変更そのものなので、同じ引き継ぎメモを書けますし、**まだ開始しない**も同じように使えます（ステータスだけ変えて、エージェントは起こしません）。この確認ダイアログは、`backlog`・`done`・`cancelled` 以外のカテゴリへ移動するときに表示されます。

この挙動は `backlog` カテゴリだけで、そのカテゴリの[カスタムステータス](/issues#カスタムステータス)もまったく同じように振る舞います。すでに `done` や `cancelled` にあるイシューは、エージェントに割り当て・再割り当てすると、すぐに実行が開始されます。

## executor の権限

エージェントを割り当てられるかどうかは、その Access で決まります。

- **自分のみ**: エージェントの owner だけが実行できます。
- **特定のメンバー**: owner とリストに載ったメンバーが実行できます。
- **ワークスペース全体**: すべてのワークスペースメンバーが実行できます。

ワークスペースの owner と admin はエージェントを管理できますが、「見える」ことは「実行できる」ことを意味しません。executor ピッカーでは、実行権限のないエージェントは選択できません。完全なルールは[エージェント](/agents#権限と-access)を参照してください。

## ロールの変更と解除

executor を別のエージェントに変更すると、新しい executor による実行が新たに開始されます。owner や reviewer を変更してもロールが変わるだけで、AI コーディングツールは呼び出されません。ロールを外してもタスクは作成されません。

<Callout type="warning">
ロールの変更、ロールの解除、イシューのステータス変更では、すでに開始された実行は停止しません。中断するには、Agent スレッドで該当するタスクを停止してください。
</Callout>

## CLI での操作

```bash
patchbay issue update PB-42 --executor "Agent name"
patchbay issue update PB-42 --executor-id <agent-uuid> --no-start
patchbay issue update PB-42 --owner-id <member-uuid> --no-start
patchbay issue update PB-42 --reviewer-id <actor-uuid> --no-start
patchbay issue status PB-42 in_progress --no-start
```

スクリプトではロール別の UUID フラグを使うと、同名のオブジェクトへの誤マッチを避けられます。UUID は `patchbay agent list --output json` または `patchbay workspace member list --output json` で確認できます。

ロールだけを記録し、新しいタスクを作成しない場合（たとえば同じエージェントが別の実行ですでにそのイシューを処理している場合）は、`--no-start` を使用します。`issue update` と `issue status` でも同じフラグを使用できます。ロールとステータスの両方を変更する場合は、両方のコマンドにこのフラグを指定してください。ロール変更を抑止しても、後続のステータス変更による実行は自動では抑止されません。
