Install a Feishu Bot for the Patchbay workspace and team members can DM it in
Feishu, @-mention it in a group, or use `/issue` to create issues. Conversations
and run records are still saved to the Patchbay workspace.

The installation is workspace-scoped rather than tied to one computer or
agent. Members can choose or switch the active agent with `/agents`; add a
dedicated installation only when a separate Bot identity is required.

## Connect a Bot

Workspace owners and admins can start a connection:

1. Open **Settings → Integrations** and click **Bind to Feishu**.
2. Choose the workspace-level installation.
3. Scan the QR code with Feishu and confirm the authorization.
4. Return to Patchbay. Once the page shows **Connected to Feishu**, the Bot is ready for the workspace.


The QR code is a one-time credential; if it expires, generate a new one. An agent that is already connected no longer shows the scan entry point; to rename the Bot or adjust its permissions, click **Manage in Feishu**.

<Callout type="info">
New connections are currently open only for mainland-China Feishu. Existing international Lark connections keep working and can still be managed.
</Callout>

## First use

The first time a member messages the Bot, they receive an account binding link:

1. Open the link and sign in to Patchbay.
2. Confirm the workspace account to link.
3. Return to Feishu and send the message again.

Only after binding can Patchbay confirm which workspace member a message comes from. Non-members cannot use the Bot.

## Hand work to the agent in Feishu

### Direct messages

Message the Bot directly. Consecutive messages stay in the same Patchbay conversation, and the agent's replies go back to that conversation.

### Group chats

Add the Bot to the group first, then `@Bot` and describe what you need. The Bot only responds to messages that explicitly @-mention it; when it runs, it draws on the recent context it can read in the current session.

### Create an issue

Send:

```text
/issue Fix the redirect after login
Safari stays on the login page after a successful sign-in.
```

The first line becomes the title and the rest becomes the description. Sending `/issue` alone creates nothing; the Bot replies with the required format instead.

## Manage connections

Open **Settings → Integrations** to view the Bots connected in the workspace. Workspace owners and admins can disconnect them here; an agent's owner can also manage their own Bot from that agent's **Integrations** page.

After disconnecting, the Bot stops receiving new messages. Existing conversations and audit records are not deleted.

## Self-hosting setup

Patchbay Cloud needs no extra configuration. A self-hosted deployment is
server-managed: the app is read-only and does not accept Bot credentials.
Follow the [self-hosted messaging deployment contract](/self-host-messaging)
and run the setup helper on the server.

```dotenv
PATCHBAY_LARK_SECRET_KEY=<base64-encoded 32-byte key>
```

Generate one like this:

```bash
openssl rand -base64 32
```

Set `PATCHBAY_MESSAGING_BOOTSTRAP=true` with the server-owned workspace and
installer IDs, add the Lark credentials to the deployment secret store, then
restart the API server. Keep this key long-term: if it is rotated or lost,
existing credentials can no longer be decrypted. Do not expect a Connect
button in the self-hosted app.

`PATCHBAY_LARK_HTTP_BASE_URL` and `PATCHBAY_LARK_CALLBACK_BASE_URL` exist only for special deployments such as proxies and testing; leave them unset in normal operation.

## Troubleshooting

- **No bind button**: confirm the current account is the agent's owner or a workspace owner or admin, and check that the self-hosting key is configured.
- **QR code expired**: close the dialog and start the connection again.
- **The Bot asks for account binding**: open the binding link and sign in with the Patchbay account for that workspace.
- **The Bot doesn't run**: check whether the agent is archived and whether the [runtime](/daemon-runtimes) it uses is online.
